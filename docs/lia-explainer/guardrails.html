Guardrails

Every important rule is enforced twice -- once in the instructions, once in the search itself -- so it can't be talked around.

Here's the thing about only relying on written instructions for an AI: they can be misread, or a weird enough input can trip it up. So none of the important limits here live only in the instructions. They're also built directly into the searches, which the AI can't edit or bypass no matter what.

RuleIn the agent's instructionsIn the search itself
Time window under 24 hours, end after startAsk a clarifying question if violatedSearch refuses and returns a diagnostic row
Exact identifier formatAsk, don't guessPattern check rejects malformed input
Record limitsReports truncation to the analystHard caps: 150 rows per source, 1024-character detail fields
One approved data setRefuses other workspacesBaked into the tool's setup, not something typed in
Tool allow-listOnly 8 named tools in its skill listThe connector's allow-list rejects anything else
Untrusted log textTreats file names, URLs, command lines as data, never as instructionsRaw values confined to one "Details" field

How each data source gets graded

Each data source reports a status, not just its results. This lets LIA distinguish an empty search from missing data, denied access, or a failed query, and explain the difference in the report.

LabelWhat it means in plain terms
ObservedThe search ran fine and found matching records.
NotObservedThe search ran fine, the data's in range, there just weren't any matching records.
UnavailableThat table doesn't exist here, doesn't apply, or the time window is too old to still be stored.
AccessDeniedThe analyst's own permissions blocked the search from running.
QueryFailedSomething else broke -- a timeout, or a guard rule rejected the input.

One thing worth knowing: if a device is outside an analyst's permission scope, the search can come back with zero rows and no error message at all. That would look exactly like "nothing happened" if LIA didn't call it out. So the report always adds a note that NotObserved only means "nothing visible to this analyst," not "nothing occurred."

What LIA will not do, on purpose

  • No remediation. It can't isolate a device, disable a user, or change anything. Read-only, full stop.
  • No free-form searches. The AI can never write or run its own custom search, ever.
  • No reaching outside the approved data set. One workspace per deployment, no exceptions.
  • No silent guessing. Anything ambiguous stops the flow with a question instead of an assumption.
