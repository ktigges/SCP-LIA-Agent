Flow

How the analyst actually uses this

An analyst opens Security Copilot and picks the LIA agent from the agent picker, the same way you'd pick any other Copilot skill. From there it's a normal chat. No KQL, no portal to dig through, no separate tool to learn.

The analyst types a question in plain English, something like:

"What did DESKTOP-FIN07 do between 8am and 6pm yesterday, Mountain time?"

LIA doesn't take that sentence and let the AI write its own database query against it. It runs a fixed sequence of pre-approved steps instead -- the same eight steps every time, in the same order. Each step checks its own work before the next one is allowed to run. That's the whole point of this page: showing exactly what those eight steps are and what each one checks for.

What comes back

If everything checks out, the analyst gets a written report back in the chat -- ten sections, same order every time, every fact in it pointing back to a specific log row so it can be checked by hand if something looks off. No isolating devices, no disabling accounts -- LIA only reads and reports.

If something's missing or too vague -- no timezone, a device name that matches two machines, whatever -- the analyst gets a question back instead of a guess. Answer it, and LIA picks up where it left off.

Once the first report's in, the analyst can keep asking follow-up questions in the same conversation -- "did that IP show up anywhere else that day?" -- and LIA answers from data it already pulled. If the follow-up needs new data, it says so and runs the next approved step for it, rather than guessing from what it already has.
